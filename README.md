# SCRP

C++17 / SDL2 движок для воссоздания старых игр. Название от **scrap** —
обрывки, старое и потрёпанное. Начало положено ядром Scrapheart;
FirstDawn стал вторым потребителем.

Это единственный исходный репозиторий общих компонентов:
[Torward1024/SCRP](https://github.com/Torward1024/SCRP).
Графика, данные и правила конкретных игр сюда не входят.

## Что уже есть

| Target | Возможности | Зависимость |
|---|---|---|
| `SCRP::Core` | JSON, ресурсные слои и пакеты, индексные изображения, BMP | Стандартная библиотека C++17 |
| `SCRP::SDL2` | Окно, целочисленный масштаб, пиксельный вывод | SDL2 |

JSON проверяет числа, Unicode, повторные поля и предел вложенности.
VFS читает каталоги и пакеты SCRP v1, поздние слои перекрывают ранние.
Пакеты совместимы с Scrapheart. Монтирования используются в главном потоке.
PixelWindow не задаёт разрешение или игровой цикл — это выбирает приложение.

## Структура

```text
include/scrp/       публичные заголовки
src/               реализации общих модулей
tests/             тесты ядра и синхронизации зависимостей
tools/             bootstrap для игр-потребителей
docs/              архитектура и подключение
build.ps1          независимая Windows-сборка Core
CMakeLists.txt     общий CMake API
```

## Сборка

На Windows используется MSYS2 UCRT64, как в Scrapheart и FirstDawn.

```powershell
.\build.ps1
.\build.ps1 -Test
```

Скрипт собирает `build/libscrp_core.a` либо запускает тесты Core.
Для SDL2-модуля и переносимой сборки используем CMake:

```sh
cmake -S . -B build/cmake -DSCRP_WITH_SDL2=ON
cmake --build build/cmake
ctest --test-dir build/cmake --output-on-failure
```

Без SDL2: `-DSCRP_WITH_SDL2=OFF`. Это сборка Core для тестов/инструментов;
игровые окна используют SDL2-модуль.

## Подключение к игре

```cmake
add_subdirectory("${SCRP_ENGINE_DIR}" scrp)
target_link_libraries(my_game PRIVATE SCRP::Core SCRP::SDL2)
```

Каждая игра хранит `scrp.lock.json` с URL и полным SHA коммита.
Обычная сборка сама обеспечивает эту версию через `tools/sync_engine.py`.
Чистый соседний checkout `../SCRP` с нужным SHA используется обеими играми.
Иначе используется игнорируемый `.deps/SCRP` конкретной игры. Checkout
разработчика не переключается, его правки не затрагиваются.

Обновление зависимости выполняется явно в каталоге игры:

```sh
python tools/sync_engine.py --update
```

Затем нужно собрать игру, выполнить тесты и закоммитить новый lock-файл.
Для разработки незакоммиченного SCRP используется явный `-EngineDir` либо
`SCRP_ENGINE_DIR`; этот режим сознательно обходит закреплённую версию.
Подробнее — [подключение и версии](docs/DEPENDENCIES.md).
