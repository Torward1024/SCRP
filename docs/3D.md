# Optional 3D modules and C17 interface

`SCRP::Physics3D` and `SCRP::Render3D` are opt-in C++17 implementations with a
C17-compatible public interface in `include/scrp/c/`. They introduce no game
rules. Existing SDL_Renderer consumers keep their presentation path and do not
download Jolt when physics is disabled.

```sh
cmake -S . -B build/3d -DSCRP_WITH_PHYSICS3D=ON -DSCRP_WITH_RENDER3D=ON
cmake --build build/3d
ctest --test-dir build/3d --output-on-failure
```

Physics needs CMake 3.20 or newer. Render3D requires SDL2 and OpenGL 3.3 core.
`SCRP_TEST_RENDER3D=ON` adds the native OpenGL lifecycle test; it needs a real
graphics context and cannot use SDL's dummy video driver. Headless physics tests
need no SDL or GPU. Link a C application's final executable with the C++ linker.
The public headers contain no C++, SDL, OpenGL or Jolt types.

## Ownership and coordinates

- Initialize owning output pointers to NULL. Failed creation leaves them unchanged.
- Destroy takes a pointer to the owning handle and clears it; NULL is safe.
- Worlds own bodies; views own meshes. IDs are process-unique and checked against
  their owner. Removed IDs and IDs from another owner are rejected.
- Use each owner on one thread. Render3D belongs on the main thread. Do not use
  an owner after destroying it or initialize a second copy of Jolt in the process.
- Operations return 1 for success and 0 for failure, with an optional caller-owned
  error buffer. Exceptions are contained by the C boundary. Memory exhaustion
  inside the external physics backend is not a recoverable simulation guarantee.
- Units are meters, kilograms, seconds and radians. Coordinates are right-handed,
  with Y up. Quaternions use XYZW and must be unit length. Math and pose interpolation
  live in Core; interpolated poses use the shortest quaternion path.

## Physics

Jolt 5.3.0 is pinned to `0373ec0dd762e4bc2f6acdb08371ee84fa23c6db` and its archive
SHA256 is checked by CMake. Source and build outputs stay in the build dependency
cache. `FETCHCONTENT_SOURCE_DIR_JOLT` is an explicit development/offline override;
it must contain that same source revision. `FETCHCONTENT_FULLY_DISCONNECTED=ON`
requires an already populated dependency cache. See the [Jolt MIT notice](../licenses/Jolt-MIT.txt).

The initial API supplies static/dynamic boxes, shape-derived inertia, gravity,
forces and impulses at world points, teleport/reset, state queries, sleeping,
optional continuous collision detection, closest-hit rays and oriented cylinder
sweeps with surface normals and point velocity. A world has bounded capacity and uses a single-thread job
system. The default contact slop is 2 mm. No worker thread is created per body.

Apply forces, step once, then read the new state. A step must be in
`0.000001..1/30` second; fixed 120 Hz is a consumer choice. A force is consumed by
the next step, while an impulse changes velocity immediately. Static bodies ignore
forces/impulses. Teleport resets velocities and accumulated forces. An update
capacity error may occur after partial simulation; stop the caller's run on error.

After a successful step, `scrp_world_impact_count` and `scrp_world_impact_read`
expose closing contacts for that step. Each event identifies both bodies, a
world-space centroid, a surface point and outward normal in each body's frame,
and the relative normal closing speed in m/s. The estimated normal impulse in
N·s uses the effective mass at the contact, rotational inertia and restitution.
Sustained contact is suppressed. Teleporting or removing a body invalidates its
entries. Consumers can copy events before the next step.

Input limits protect the backend: box half-extents `0.01..10000`, dynamic mass
`0.001..1e8` (zero is static), friction `0..2`, restitution `0..1`, damping `0..10`,
position/ray components within `+/-1e6`, gravity components within `+/-1e4`,
force/impulse components within `+/-1e9`. A world supports `2..65536` bodies.
These are API limits, not accuracy guarantees for extreme scales.

`scrp_world_cast_cylinder` sweeps a finite cylinder (axis local Y) along a world
displacement, ignoring one owned body. A unit axis and minimum dot product filter
out unwanted surface normals before choosing the nearest accepted hit. Initial
overlaps report fraction zero and penetration depth. Edges use an internal convex
margin of at most 1 cm while keeping outer dimensions. Nearly parallel GJK and
geometric face normals are reconciled to avoid lateral bias on large flat faces;
actual edge/corner separation normals remain intact. Cylinder radius and half-height
are in `0.001..1000`; the displacement must be finite and nonzero.

Constraints, contact-event/impulse streams, additional sweep shapes, shape catalogues and
serialization are future extensions. Suspension, tires, drivetrain and collision
damage policies belong in consumers. No Jolt vehicle implementation is exposed.

## Presentation

A view owns an SDL OpenGL window/context, shader, mesh buffers, textures and overlay stream.
The module provides perspective cameras, triangle meshes, box/cylinder primitives,
per-vertex colors, directional lighting, two generic spotlights and distance fog.
Draw scene meshes first, then the overlay. `present` optionally captures the back
buffer as BMP before swapping. The existing MicroFont glyph masks are shared with
the HUD, without creating an SDL_Renderer in an OpenGL window.

Mesh upload copies caller data. `scrp_view3d_mesh_update` replaces an owned mesh's
triangle stream after validating all input; stale or foreign handles fail.
Drawing accepts a pose, positive XYZ scale, tint
and emissive factor. Polling reports elapsed time, focus and window close events;
key queries take SDL physical key names. Action bindings remain consumer policy.

To draw a texture atlas, pass triangles of `scrp_uv_vertex` to
`scrp_view3d_uv_mesh_create`, then load a BMP once with
`scrp_view3d_texture_load_bmp`. The latter accepts a UTF-8 filesystem path
and uploads the image as RGBA with bilinear filtering and mipmaps. UV (0,0)
addresses the top left of the decoded image. UV (1,1) addresses the bottom right.
Sampling clamps to the image edges. Allow padding around atlas islands.

Pass the mesh and texture IDs to `scrp_view3d_draw_textured`. Vertex color and
draw tint multiply the sampled color before lighting and fog. Several UV meshes
or instances can share one texture. UV meshes are immutable. Plain meshes retain
their original vertex layout and dynamic-update API. Destroy individual textures
with `scrp_view3d_texture_destroy` or release them together by destroying the view.

## Model resources (Core)

Load a GLB 2.0 file with `scrp_model_load_glb` from `scrp/c/Model.h`, or pass
bytes from a VFS mount to `scrp_model_decode_glb`. Enumerate mesh primitives
or look one up by glTF mesh name and zero-based primitive index. The model
owns the returned arrays and encoded image data until `scrp_model_destroy`.
Meshes use local coordinates. Applications choose which instances to draw
and supply their node transforms.

Each primitive provides a `scrp_vertex` array suitable for deformation and
plain mesh upload. A primitive with TEXCOORD_0 also provides `scrp_uv_vertex`
for textured mesh upload. The reader expands triangles in draw order, including
8-, 16- and 32-bit unsigned indices. POSITION and NORMAL use float VEC3.
Missing normals use the triangle's face normal. COLOR_0 accepts RGB or RGBA,
defaults to white and supplies alpha 1 for RGB. Both colors and UVs accept
float, normalized unsigned byte or normalized unsigned short components.
The reader handles accessor offsets and interleaved vertex buffers.

For a textured material, use the primitive's `base_color_image_index` with
`scrp_model_image_data` to obtain the embedded PNG or JPEG, its byte length and
MIME type. A value of -1 means the material has no base color texture.
Applications can also enumerate all embedded images. File paths use UTF-8.
The supported subset requires a single embedded buffer, TRIANGLES geometry
and dense accessors. Limits are 128 MiB per GLB, 8 MiB of JSON and three million
expanded vertices per model. [glTF 2.0 specification](https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html)

With `SCRP_RENDER3D_PNG=ON`, Render3D links libpng and exposes in-memory decoding via
`scrp_view3d_texture_load_png`. Pass the encoded bytes and byte count returned by
`scrp_model_image_data` for a PNG embedded in a GLB. Upload copies the decoded pixels
into the view. The model can be released after its meshes and textures are uploaded.
Both texture paths use a top-left origin and accept dimensions up to 8192 per side.

## General deformation (Core)

`scrp/c/Mesh.h` supplies a bounded, optional-weight displacement field on triangle
vertices, rebuilding flat normals and axis-aligned bounds without allocation or a
graphics context. Vertex colors are retained. Weights in `0..1` protect selected
vertices; each weighted displacement is capped by the caller's finite limit.
Invalid input leaves output and bounds untouched. Source/output may be the same
buffer; otherwise buffers must not overlap. Displacements and weights must stay
separate from output storage. The caller chooses whether to accumulate permanent
deformation or rebuild elastic geometry from a pristine source. Regions, materials,
collision response and recovery policy remain consumer-owned.

`scrp_mesh_dent_uv` applies bounded ellipsoidal displacement fields to
pristine textured triangles and rebuilds bounds. It preserves UVs and colors,
turns authored normals with affected faces, and supports per-vertex protection
weights. Passing an empty field restores the original vertices. An OpenGL
consumer can upload the result into an existing textured mesh with
`scrp_view3d_uv_mesh_update`. Consumers own the persistent fields and decide
when an instance needs a new upload.

## Validation

C translation units exercise falling/resting bodies, equal gravitational
acceleration at different masses, off-center impulses, reset, rays, ownership,
invalid values and continuous collision through a thin floor. Sweeps cover initial
overlap, normal filtering and support over an edge missed by a center ray. Core's
C17 mesh contract covers displacement limits, protected vertices, flat normals,
bounds, invalid-input atomicity, in-place updates and pristine-source recovery.
Native OpenGL tests cover context coexistence, mesh ownership, dynamic updates,
frame order and overlay drawing. A four-color atlas round trip checks the captured
pixels for UV orientation, texture ownership and switching back to a plain material.
Core and the existing SDL suites remain independent of these opt-in dependencies.
