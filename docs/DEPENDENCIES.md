# Подключение SCRP

Игра хранит `scrp.lock.json`: `schema_version: 1`, URL SCRP и полный SHA коммита.
Канонический `tools/sync_engine.py` находится здесь; обе игры содержат идентичную
копию bootstrap, чтобы первая сборка могла получить зависимость.

## Обычная сборка

1. Явный `--engine-dir` / `SCRP_ENGINE_DIR` использует рабочие исходники напрямую.
2. Без override создаётся или проверяется игнорируемый `engine/SCRP/` игры.
3. Недостающий коммит скачивается; управляемая копия закрепляется на нужном SHA.
4. Локальные правки или чужой origin в кэше вызывают ошибку без перезаписи.

Соседний рабочий SCRP автоматически не выбирается и не изменяется. Если коммит
уже получен, сеть не нужна. `--offline` запрещает загрузку и сообщает об отсутствии
зависимости. Обычная сборка не изменяет lock-файл и не следует за свежим main.

## Разработка и обновление

```powershell
# Проверка незакоммиченного движка из каталога игры:
.\build.ps1 -EngineDir E:\Dev\SCRP
```

В CMake override — `-DSCRP_ENGINE_DIR=...`; в Make — `SCRP_ENGINE_DIR=...`.
Проверяем Core/SDL и обе игры, публикуем коммит SCRP, затем в каждой игре:

```powershell
python tools/sync_engine.py --update
.\build.ps1 -Test
.\build.ps1
```

`--update` получает SHA remote main, обеспечивает checkout и лишь затем атомарно
заменяет lock-файл. Тесты потребителя запускаем отдельно. Игры могут переходить
на новую версию независимо. Не редактируем `engine/SCRP/` вручную; все общие
изменения делаем в исходном репозитории движка.
